## Design systems

Most of my recent work has been on design systems: libraries of web components, built with StencilJS and TypeScript, that product teams use from whichever framework they run: Angular, React or Vue. The components are rarely the hard part. The hard parts are a stable API, documentation that answers the next team's questions before they ask, a release process people trust, and helping teams integrate the library into their applications.

I've built design systems for a large German public-sector organisation and for a global market research company. In both, accessibility was a requirement from the first component, not an audit at the end.

## Applications

For applications, Angular is the framework I know deepest, and I've reviewed and supported integration work in React and Vue. I've led the frontend of a large master data system and helped move a business-critical desktop application to the web, including a Node.js backend-for-frontend.

## How I work

I work closely with UX and product owners on requirements, review code across teams, and write unit and end-to-end tests from the start. Where a team needs it, I also set up the CI/CD pipeline that ships it.
